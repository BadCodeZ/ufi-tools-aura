# AURA v2.5.3 更新说明

> 基线 v2.5.2 / BUILD 1117a → **v2.5.3 / BUILD 1117b**
> 内容：处理 AdGuardHome 默认口令提醒——先修正检测链路的语义错位，
> 再因设备侧无法改密而移除这条做不到的提示。检测能力保留，界面不再打扰用户。
> 可整版退回 v2.5.2（回退方式见文末）。

---

## 一、问题现象

用户反馈：ADG 默认口令「修改也没用，也检测不了，整个链路好像是坏的」；
后续核实「ADG 内我没找到修改密码的地方」。

安全提醒条一直显示「AdGuardHome 自某日起未变（root / root）」，按提示去改口令后提醒不消失，重新检测也无变化。

## 二、根因（真机取证，非猜测）

在 F50 / ADG 真机上读 shell 与配置，确认**检测对象和引导用户改的对象根本不是同一个密码**：

| 项 | 检测读的东西 | 旧版引导去改的东西 |
|---|---|---|
| 位置 | `AdGuardHome.yaml` → `users.password` | `/data/agh/.aura/cred`（API 凭据缓存） |
| 性质 | ADG 官方面板的**登录口令**（bcrypt） | AURA 自己访问 ADG API 用的账号口令 |
| 改它影响检测 | 是 | **否** |

取证记录：

- 真机 `sed -n '/^users:/,/^[^[:space:]]/p' /data/agh/agh/bin/AdGuardHome.yaml` 返回
  `users: / - name: root / password: $2b$12$…`，说明**读取端正常**，正则能解析、指纹能算出；
- `adg.sh` 的 `cred)` 分支（第 33 行）只写 `.aura/cred` 后登录验证，**完全没碰 yaml 的 password**；
- 本地基线 `aura_secev` 里 `agh.d` 与当前 yaml 指纹一致、`s=first`，状态机本身没错。

> 排查中还否掉过一个假根因：怀疑 `sed '/^users:/,/^[^[:space:]]/p'` 的结束模式会在同一行匹配 `users:` 自身导致只打印一行。
> 实测 GNU sed 第二地址从下一行才开始判断，当前写法能正确读到 password 行，排除。

## 三、为什么最终移除了提示

第一轮修复把「去修改」指向 ADG 官方面板，但真机进一步核实发现**这条路走不通**：

- **面板版本 v0.107.71 没有改密入口**。设置页只有常规 / DNS / 加密 / 客户端 / DHCP 五项，无任何密码控件；
  顶部菜单只有仪表盘 / 查询日志 / 设置 / 过滤器 / 登出；登录页「忘记密码？」在这个精简版里也点不出来。
- **设备上没有任何 bcrypt 生成工具**：`htpasswd` / `openssl` / `python` / `perl` 全无，toybox / busybox 也不带。
- **AdGuardHome 二进制没有改密参数**：`--help` 全量参数无 `--update-password`。
- **前端也没有 bcrypt**：AGH 的 `main.js`（3.5 MB）里搜不到 bcrypt / blowfish，密码校验在服务端。
- **AURA 内置改密塞不下**：本地 bcryptjs（41.5 KB）最小裁剪也要 15~20 KB，远超体积阻断线余量。

结论：这条提示指向一个**做不到的操作**，既无法改密、又无法消除提醒。按用户要求移除提示，不增加体积、不增加功能。

## 四、改了什么

**第一轮（检测链路语义修正）**：`secGuide('agh')` 曾把用户引导到 `#adg-cp`（API 凭据），与检测对象无关；已改为指向官方面板。检测逻辑（读 yaml → 算指纹 → 与基线比对 → 出状态）本身一行没改。

**最终（移除展示）**——只动展示层，检测链路完整保留：

| 位置 | 改动 |
|---|---|
| 告警条渲染 `secRefresh` | `secWeak()` 结果过滤掉 `k==='agh'`，ADG 项不再出现在提醒里 |
| 「重新检测」计数 | 同步过滤，避免「2 项仍需处理」却只显示 1 项的错位 |
| 安装完成引导 `secInstalled` | AGH 装完不再弹「请修改默认管理口令」弹窗 |

**保留不动**：`secProbeAgh` 仍读 yaml 算指纹、基线仍写 `aura_secev`、散列仍不进 DOM / localStorage、OpenList 的默认口令提示照常显示。
